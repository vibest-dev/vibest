# Effect Services

1. A service is a `Context.Service` class. Its production layer is `static readonly layer`; a layer that takes options is `layerWith(options)`; a test double for it is `testLayer`, next to the service when it has no test-only dependencies. The effect that builds the service is `make` (a value, or a function when it takes arguments). Do not add `live`, `Live` or plural `layers` names.
2. A value the host must supply (the daemon's identity and shutdown signal, the host environment) is a `Context.Service` with no default, so a missing wire fails to compile. Use `Context.Reference` only when its default is correct in production.
3. A service method's requirements are `never`: resolve dependencies when the layer is built and close over them. Do not hand `Scope`, `FileSystem` or another service to callers through a method's type, and do not capture a context to `provideContext` it back into a method.
4. Failures at the platform boundary are `Schema.TaggedError`s (`LockFailed`, `DatabaseOpenFailed`, `SchemaMismatch`), never a plain `Error` or `unknown`; new `Effect.tryPromise` and `Effect.try` calls pass a `catch` that maps to one.
5. A public service method is `Effect.fn("Service.method")`, so its span and stack name it. A new log line puts ids and the cause in structured fields (`Effect.logWarning("message", { "session.id": id, cause })`), not spliced into the text. Convert existing methods when you touch them; there is no sweep.
