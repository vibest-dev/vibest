# Effect Services

1. Following Effect, code takes every dependency (`FileSystem`, `Path`, `ChildProcessSpawner`, clients, other services) from the service graph it runs in, resolved when its layer or the composition is built and closed over. Nothing builds its own platform layer or a service instance inside a method or at module level (for example a plugin providing `NodeFileSystem.layer` itself).
2. A service is a `Context.Service` class. Its production layer is `static readonly layer`; a layer that takes options is `layerWith(options)`; a test double for it is `testLayer`, next to the service when it has no test-only dependencies. The effect that builds the service is `make` (a value, or a function when it takes arguments). Do not add `live`, `Live` or plural `layers` names. Its place in the service graph is `static readonly node = LayerNode.make({ service, layer, deps })`, whose `deps` list the node of every service the layer reads (the type check refuses a missing one); a node built from options is `configured(options)`. Wire a service through `deps` and replacements ([architecture §5](../../docs/design/architecture.md#5-service-composition)), not with `Layer.provide` chains at a root.
3. A value the host must supply (the daemon's identity and shutdown signal, the host environment) is a `Context.Service` with no default, so a missing wire fails to compile, and its node is `LayerNode.unbound(Service)`, so a graph that reaches it without a replacement fails when it is compiled. Use `Context.Reference` only when its default is correct in production.
4. A service method's requirements are `never`: resolve dependencies when its layer or the composition is built and close over them. Do not hand `Scope`, `FileSystem` or another service to callers through a method's type, and do not capture a context to `provideContext` it back into a method.
5. Failures at the platform boundary are `Schema.TaggedError`s (`LockFailed`, `DatabaseOpenFailed`, `SchemaMismatch`), never a plain `Error` or `unknown`; new `Effect.tryPromise` and `Effect.try` calls pass a `catch` that maps to one.
6. A public service method is `Effect.fn("Service.method")`, so its span and stack name it. A new log line puts ids and the cause in structured fields (`Effect.logWarning("message", { "session.id": id, cause })`), not spliced into the text. Convert existing methods when you touch them; there is no sweep.
