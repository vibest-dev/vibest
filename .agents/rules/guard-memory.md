# Guard and Memory

1. Every new path that opens a terminal passes the session identity environment, so both `VIBEST_PROJECT_DIR` and `VIBEST_SCRATCHPAD_DIR` are set and granted to the harness without permission prompts (Claude: `permissions.additionalDirectories` in inline `--settings` plus `Read`/`Edit` allow rules; Cursor and agy: `--add-dir`; never `--add-dir` on Claude, which also loads skills/commands/agents and prompts).
2. **Strict `VIBEST_SCRATCHPAD_DIR` vs `$VIBEST_PROJECT_DIR/artifacts/` boundary**:
   - `$VIBEST_SCRATCHPAD_DIR` (`<os.tmpdir()>/vibest-<uid>/<project-id>/scratchpad`, `0700` parent, scoped at the project level mirroring `VIBEST_PROJECT_DIR`) holds all temporary agent-to-agent handoffs, `--file` task briefs, review notes, repro scripts, and scratch files. `vibest archive` does **not** delete the scratchpad directory—it stays in OS temp so parent agents and users can still inspect scratchpad files after archiving and OS reboot cleans it naturally.
   - `$VIBEST_PROJECT_DIR` has fixed subfolders `docs/`, `memories/`, and `artifacts/`. `artifacts/` is strictly for human-facing deliverables (agreed `pipeline` plans, HTML UI mockups/playgrounds, diagrams, acceptance reports, explicit user-requested reports).
   - `memories/MEMORY.md` is the curated index loaded into the system prompt (capped at 100 lines / 8000 bytes), pointing to one topic file per lesson in `memories/<name>.md` read on demand or searched with `vibest project search <query> --kind memories`.
3. Pre-tool guard checks run through `@vibest/plugin` hooks (`ctx.session.hook("tool.execute.before", ...)`). `AgentDefinition` carries no per-agent `guard` callback.
4. Core (`packages/core/src/guard.ts`) decodes harness `PreToolUse` JSON, resolves `cwd` (`input.cwd` or the single `workspace_roots[0]`, plus `tool_input.cwd` when present, handling `file://` and `~`), and calls `Plugins.Service.guard` with `{ session: { id, agent, project, projectDir }, tool, input, cwd }`. Malformed hook input still fails and refuses the call.
5. The builtin plugin `vibest.guard` (`packages/builtins/src/guard.ts`) uses only `@vibest/plugin/effect` and enforces two minimal protocol self-protection invariants on shell tools (`bash`, `powershell`, `shell`):
   - Running `vibest` with `VIBEST_SESSION_ID` assigned, exported, unset, or cleared anywhere in the command (since caller identity comes from `VIBEST_SESSION_ID`).
   - Invoking socket/HTTP tools (`curl`, `nc`, `ncat`, `socat`, `wget`) targeting `vibestd`'s Unix socket (`vibest.sock` / `vibest-http.sock`).
6. Everything else (`hc`, `rex`, `herdr`, `~/.vibest`, `gh`, file edits) is allowed by default unless a user plugin refuses it with `ToolRefused({ reason })`. Which `vibest` commands an agent may run is enforced directly where they run (`caller.ts` `userOnly`, `server.ts` `ACCESS`), not in the guard.
7. The guard checks what a tool call says; it is not a sandbox. A call is allowed unless a `tool.execute.before` plugin refuses it, and a `tool.execute.before` hook that crashes or times out is logged and skipped so a broken user plugin does not brick all tool calls.

Status: in force (`packages/core/src/guard.ts`, `packages/builtins/src/guard.ts`).
