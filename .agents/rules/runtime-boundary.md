# Runtime Boundary

The terminal runtime (herdr and hc today) is a plugin that adds a `RuntimeDefinition` (`@vibest/plugin`) with `context.runtime.transform`; core routes by its `id` and detects the caller's terminal from its optional `caller`. This is not the Bun boundary; for that see [bun-runtime-boundary.md](bun-runtime-boundary.md).

1. Core, environment names, headers and the protocol carry no runtime-specific names: no herdr pane ids, no `HERDR_*` outside `packages/runtime-herdr`. A terminal `{machine, id}` is opaque to core.
2. Runtime data travels as one opaque field: `VIBEST_RUNTIME` in the environment and the `vibest-runtime` header, for example `{"runtime":"herdr","machine":"local","terminal":"<id>"}`. It carries the terminal when it is known; a subagent env is fixed before its pane opens, so its `VIBEST_RUNTIME` has no terminal.
3. Core checks whether an optional runtime member exists (`h.state === undefined`), never which runtime it is. A new runtime operation is an optional member, added only when something needs it.
4. Never close a pane to restart, replace or move an agent. A restart ends only the harness process; the pane and its shell stay, and the optional `run(terminal, argv)` starts the next program in that shell once it is idle. A program `open` starts is typed into the terminal's shell, never exec'd, so the shell stays after it.
5. Remote machines will come. Do not bake in "local only" without naming the ceiling in the design document of that area (see [no-comments.md](no-comments.md)).
6. The runtime is the terminal, the process and the machine: open and placement, labels, close, liveness and exit, keys and reading the screen on request, machine status and setup. Agent state comes from the harness integrations, not the runtime: readiness, execution state, waiting for a permission decision, and the conversation id.

Status: 1 and 3 are in force on main for core, with one leftover: `packages/core/src/guard.ts` refuses `herdr` commands by name. 2 is decided, on `feat/claude-http-transport`. 4 is decided; main still closes the pane in the usage-limit move (`packages/core/src/move.ts`); on `feat/update-restart-agents-v3` the restart and the move use `run` (runtime-herdr: agent.start for a harness, else the line typed once the shell is idle), and the move closes the pane only for a runtime without `run` or a harness that reported no pid. 5 is a direction. 6 is decided; readiness by the integration is built on `feat/update-restart-agents-v3`. On main the runtime still supplies the agent state, blocked included (`state`, from herdr agent detection), and the Cursor conversation id (`session`), both to move later.
