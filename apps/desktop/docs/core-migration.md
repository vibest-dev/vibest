## Implementation map

1. `internal/core`: explicit endpoint resolution; plain hello followed by framed JSON-RPC; bounded independent attach/event streams, flow credit, cancellation and connection lifetime. No legacy protocol and no implicit start/connect helper.
2. Client session: Core terminals and program-reported status; Reherdr-owned versioned layout document, local keyboard/focus/zoom ownership; distinct frontend and terminal identities. Subscribe before document reads; conflict never overwrites another writer.
3. Frontend: replace backend topology calls with client model operations; use MyGo's VT terminal for Core bytes and mode-aware input. Preserve navigation/layout/chrome; cancel captured input on ownership, connection or attach loss. No synthetic boot/projection values.
4. Remove legacy discovery/SSH/process assumptions; expose Core machines and conservative close confirmation; audit remaining feature gaps.

## Implemented seams and remaining integration

- `core.Connect` owns a supplied connection; `Dial` directly dials the explicit Unix socket and never invokes an autostart helper. Hello strictly requires 0.1.13/generation 1 and the used methods/features. `EndpointFromEnv` follows HC/XDG defaults; if a Core TOML config exists, this checkpoint requires `-core-socket`/`HC_SOCKET` rather than silently ignoring or partially parsing its socket setting. Windows named pipes are not implemented.
- A local `Viewer` provides a connection/channel incarnation; the client ends captured input on CLOSE, loss/restart events or client connection end. **Remote relay channels do not provide that guarantee.** Core0.1.13 retains them through line loss and can reattach before `documents_missed`. Remote human input is therefore refused in the module and the App, with an explicit reason, even after a new paint or focus return. This is a remaining remote migration/parity gap, not completed remote support or a weakened acceptance boundary.
- `Keyboard` provides immutable per-selection input captures and a local rendered gate. It never uses permanent Core ID, event seq or document version as render freshness. A new session/attach needs new captures. The module does not retain/replay a FIFO across reconnect.
- `coreview` uses MyGo's existing VT parser, software/native renderer and mode-aware encoder. Patch 0009 captures the writer before MyGo queues input, bounds owner-aware queue memory/entries, cancels deferred paste/composition, distinguishes canceled writes from a broken queue, and exposes one fitted-paint callback carrying actual grid and pixel cell dimensions. The narrow OnOutput hook now classifies Core’s initial 9001 marker only after the toolkit parser consumes it. Missing or partial markers leave input closed; the supported Unix marker must also be followed by an unheld fitted paint. A received-but-unparsed byte does not establish readiness; a synchronized-update-held paint does not establish it either. A stale selection frame or clipped grid cannot establish readiness, and a changed grid/cell size invalidates prior leases.
- The `reherdr-layout` document is schema 1, validated and CAS-written. It never writes Desktop's `herdr-app` document. Local workspace/tab/pane IDs remain distinct from Core addresses, including pinned remote Core identities. Selection/zoom are window-local. Split, ratio, rename, reorder, swap, pane move and removal have model implementations; the existing App actions now call them; full layout/interaction parity remains unverified.
- A canceled topology write has uncertain outcome and closes the connection for fresh reconciliation rather than replaying the edit. A CAS conflict refetches the winning document without automatically applying the stale edit again.

## Queue-ownership follow-up milestone

Public patch shape (all on the existing MyGo0.6 terminal, no new policy framework):

```go
Options.CaptureInput func() io.Writer
Options.InputLimit int
Options.OnInputError func(error)
Options.OnOutput func([]byte)
Options.OnPaint func(cols, rows, cellWidth, cellHeight int)
Terminal.CancelInput()
terminal.ErrInputCanceled
terminal.ErrInputFull
```

The only production hook caller is `internal/coreview.New`: CaptureInput freezes one `core.Input` before MyGo's first asynchronous enqueue. That same value reaches `Input.Write`, which copies bytes into Core's queue with an admission closure over the original viewer/generation. Dispatch validates that immutable lease; it never recaptures the current owner. `coreview.Select`, `Cancel` and `CancelComposition` invalidate leases before clearing deferred toolkit captures, retaining the same VT renderer, screen/scrollback and viewport.

MyGo0.6's existing terminal View installs its private paint function via Draw; the caller cannot observe completion or actual grid/cell dimensions without replacing that draw function. Thus the narrow OnPaint hook is needed. `coreview.View` captures the selection incarnation when building the view. OnPaint reports the complete grid and pixel cell size actually drawn; zero means no parsed/fitted grid. Core checks the captured selection, the specific painted viewer (not its selected sibling), attach lifetime and geometry. Geometry changes invalidate old input even if the grid later returns to the former dimensions. No backend revision or render fence is invented.

**Unavoidable boundary:** the final admission check is the dispatch/in-flight boundary. An admitted write still targets its original channel but cannot be recalled if focus changes while the socket write is in flight. Input locks are released before socket I/O; subsequent queued old captures are rejected instead of delaying focus loss behind a blocked write.

## Activity/navigation fixture port (after review corrections)

The activity fixtures now enter through Core hello, the subscription snapshot/events and the schema-1 Reherdr document over net.Pipe. They no longer manufacture legacy Boot/projection fields or wait for focus RPCs. Explicit workspace/tab activation—including reactivating an already-selected row—and pane clicks consume only the captured reported count after successful window-local navigation. Missing/unreported data, a later count, disconnected/invalid navigation, a changed program, or another Session cannot consume that intent. Zero Core Turn means no supplied completion count; unlike the retired projection protocol, it is not a valid zero-valued completion token.

Aggregation is deterministic: reported working wins over unread completion, then error/blocked attention, then seen completion/idle/unknown. A supplied completion count survives later idle/attention status until explicitly visited. Unreported records never infer work, idle or completion. Status/ring/slot/theme tests now exercise these actual records.

Session snapshots expose the existing locally observed program-change counters so the App can discard acknowledgments and obsolete renderers after created/restarted/lost/removed events. These counters are **not** backend incarnation IDs, remote fences, completion tokens or render proofs. A new Session conservatively clears acknowledgment history: permanent Core identity alone cannot establish program continuity across missed events. Ordinary focus changes still retain the same renderer. The replacement regression checks fresh renderer/channel, invalid old capture, real viewer focus/FACTS and subsequent data. An additional actual App/software test verifies composition versus committed text, bracketed paste, selection/copy through the tester’s private clipboard, dialog text isolation and typing after dismissal without recreating the renderer.
