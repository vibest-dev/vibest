### Bounds and focused contracts

Local Git argv has at most32 entries/16KiB; cwd/paths at most4096 bytes. Execution has a5-second server timeout and bounded output. Repository metadata is at most256KiB/256 worktrees. Timeout/truncated/nonzero/invalid-base64 results fail without retry. The existing5-second/1024-event/64KiB original-intent input budget is unchanged.

- `TestGitUsesActualCoreExecContract` and `TestCoreGitRejectsUncertainOrUnboundedExecResults` use the actual framed Core method, not a fake shell command API.
- `TestGitCommandsAreBoundedArgvAndNeverForced` inspects literal branch/path argv, including metacharacters, and absence of force/shell flags.
- `TestWorktreeGitFailureAndNewerIntentKeepOriginalInputFenced` covers Git refusal, later navigation and changed source.
- `TestWorktreeRemovalIsConfirmedNonForcedAndKeepsDirtyCheckout` covers cancel, dirty refusal, successful removal and changed identity without killing terminals.
- `TestWorktreeCreatedCheckoutRemainsNamedWhenCoreRunFails` retains the created checkout path and lost-input explanation when the subsequent Core creation fails.
- Core tests cover optional Git metadata and grouped-workspace CAS reorder. Group moves no longer enter a retired workspace.move_block controller.
- Title/no-dot, scrollbar clipping, tab/corner selection and memory/streaming probes now use actual Core documents and populated VT output. The obsolete tile-key benchmark is retired; remaining frame benchmarks explicitly measure the toolkit VT renderer, not Core end-to-end performance.
