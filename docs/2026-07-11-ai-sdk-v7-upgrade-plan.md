# Monorepo `ai` v5 → v7 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade the whole monorepo from Vercel AI SDK v5 to v7 so the harness-agent ai-sdk abstraction can be built on v7.

**Architecture:** A two-major dependency bump (`ai` ^5→^7, `@ai-sdk/react` ^2→^4) across 8 packages, plus one genuine code migration — the 16 claude-code provider-tool definitions — and typecheck-driven fixes for the rest. Everything else the repo uses (`UIMessage` generics, chunk type spellings, `readUIMessageStream`, `InferUITools`/`InferUIMessageChunk`, `generateId`, and the modern `useChat` surface) is unchanged between v5 and v7, so the blast radius is small relative to the version jump.

**Tech Stack:** pnpm workspace, Vite+ (`vp`), TypeScript, Vitest, Vercel AI SDK (`ai`, `@ai-sdk/react`), Zod (`zod/v4`).

**Why first:** The harness-agent abstraction plan (`docs/2026-07-11-harness-agent-ai-sdk-package-plan.md`) targets v7 APIs. This upgrade is its prerequisite; that plan runs after this one is green.

## Global Constraints

- **Exact version targets:** `ai` → `^7.0.22` (currently `^5.0.63`, one package `^5.0.30`); `@ai-sdk/react` → `^4.0.23` (currently `^2.0.44`). No other `@ai-sdk/*` package is a direct dependency (they arrive transitively).
- **Packages declaring `ai` (8):** `apps/chrome-side-panel`, `packages/agents`, `packages/ai-sdk-agents`, `packages/server-rpc`, `packages/ui`, `packages/vibest`, `packages/vibest-devtools`, `packages/vibest-devtools-client`. Bump the pin in `dependencies`, `devDependencies`, AND `peerDependencies` wherever `ai` appears (e.g. `ai-sdk-agents` lists it in both dev + peer).
- **Packages declaring `@ai-sdk/react` (3):** `packages/vibest`, `packages/vibest-devtools-client`, `apps/chrome-side-panel`.
- **v7 migration key (the only breaking changes that touch this repo — from `ai@7.0.22` source):**
  1. Provider tool shape: `type: "provider-defined"` → `type: "provider"`; the `name` field is **removed**; a required `isProviderExecuted: boolean` is **added**. Claude-code tools are executed by the provider ⇒ `isProviderExecuted: true`. `id` and `args` unchanged; `inputSchema` stays; `outputSchema` stays (if `tsc` rejects `outputSchema` on a provider tool, drop it — the render layer never executes these tools).
  2. Unchanged and safe to leave as-is: all `UIMessageChunk` type spellings (`start`, `finish`, `text-start`, `text-delta` with field `delta`, `text-end`, `tool-input-available` with `toolCallId`/`toolName`/`input`/`providerExecuted`, `tool-output-available`, `tool-output-error`, `reasoning-*`, `data-*`); `UIMessage<METADATA, DATA_PARTS, TOOLS>` generics; `InferUITools`, `InferUIMessageChunk`; `readUIMessageStream({ stream })` (yields one accumulating message); `generateId`; `useChat` returning `{ messages, sendMessage, status, regenerate }`.
  3. v7 additive surface (new, non-breaking) you may ignore unless a switch is exhaustive: UI parts `custom`/`reasoning-file`; chunk types `tool-approval-request`/`-response`, `tool-output-denied`, `abort`, `custom`, `reasoning-file`; `UIToolInvocation` states `approval-requested`/`approval-responded`/`output-denied` and fields `approval`/`title`/`toolMetadata`. A `switch (part.state)` or `switch (chunk.type)` with no `default` may newly error on missing cases — add a `default` branch, don't enumerate them.
- **No behavior changes.** This is a dependency upgrade: the definition of done is "installs, typechecks, lints, and all existing tests pass on v7" — not new features.
- **Preflight (execution skill handles):** commit the pending design-doc + plan edits, then branch `chore/ai-sdk-v7` from HEAD. Conventional commits, **no Claude annotations**.

### Task 2: Migrate the claude-code provider-tool definitions

**Files:**

- Modify: every file under `packages/ai-sdk-agents/src/claude-code/tools/*.ts` that calls `tool({ type: "provider-defined", ... })` — the active set imported by `packages/ai-sdk-agents/src/claude-code/index.ts` is `bash.ts`, `bash-output.ts`, `edit.ts`, `exit-plan-mode.ts`, `glob.ts`, `grep.ts`, `kill-shell.ts`, `multi-edit.ts`, `notebook-edit.ts`, `read.ts`, `slash-command.ts`, `task.ts`, `todo-write.ts`, `web-fetch.ts`, `web-search.ts`, `write.ts` (16 files), plus the two currently-commented-out `list-mcp-resources.ts` and `read-mcp-resource.ts` (migrate them too for consistency).
- Test: existing `packages/ai-sdk-agents/test/schema-type-compatibility.test-d.ts` (type-level) guards the tool types.

**Interfaces:**

- Consumes: v7 `tool()` (Task 1).
- Produces: v7-valid provider tools; `claudeCodeTools` ToolSet and `ClaudeCodeTools = InferUITools<...>` still infer the same tool names (the names come from the `claudeCodeTools` object keys in `index.ts`, not the removed `name` field).

- [ ] **Step 1: Apply the mechanical transform to every tool file**

For each tool file, inside the `tool({ ... })` call: change `type: "provider-defined"` to `type: "provider"`, delete the `name: "..."` line, and add `isProviderExecuted: true`. Leave `id`, `args`, `inputSchema`, `outputSchema` untouched.

Example — `packages/ai-sdk-agents/src/claude-code/tools/exit-plan-mode.ts`:

```ts
// BEFORE
export const ExitPlanMode = tool({
  type: "provider-defined",
  id: "claude-code.ExitPlanMode",
  name: "ExitPlanMode",
  args: {},
  inputSchema: z.object({ plan: z.string() }),
  outputSchema: z.string(),
});

// AFTER
export const ExitPlanMode = tool({
  type: "provider",
  id: "claude-code.ExitPlanMode",
  isProviderExecuted: true,
  args: {},
  inputSchema: z.object({ plan: z.string() }),
  outputSchema: z.string(),
});
```

Apply the identical change to the other 17 files (same three edits: `type` value, remove `name`, add `isProviderExecuted: true`).

- [ ] **Step 2: Typecheck the package**

Run: `pnpm --filter ai-sdk-agents typecheck`
Expected: PASS. If `tsc` reports that `outputSchema` is not assignable on a provider tool, remove the `outputSchema` line from the flagged file(s) and re-run (these tools are display-only; the render layer never executes them). If it reports `isProviderExecuted` missing, confirm Step 1 added it.

- [ ] **Step 3: Run the package tests**

Run: `pnpm --filter ai-sdk-agents test`
Expected: PASS — including `schema-type-compatibility.test-d.ts`.

- [ ] **Step 4: Commit**

```bash
git add packages/ai-sdk-agents/src/claude-code/tools
git commit -m "refactor(ai-sdk-agents): migrate provider tools to ai v7 tool shape"
```
