# Distribution

Installation and update details for the [vibest surfaces](architecture.md#13-surfaces-and-protocol) and [packaging rules](../../.agents/rules/packaging-and-platforms.md).

Vibest ships as a **single self-contained compiled binary** (`bin/vibest`) across 6 Unix targets (`darwin-arm64`, `darwin-x64`, `linux-arm64`, `linux-arm64-musl`, `linux-x64`, `linux-x64-musl`). The build (`packages/cli/scripts/build.ts`) compiles with ESM AoT bytecode, isolated PGO layout (`compile.bytecodeOrder`), `compile.jitPolicy: 100` (restoring `Bun.unsafe.setJITPolicy(1)` on foreground `vibestd` startup), `execArgv: ["--smol", "--use-system-ca", "--no-warnings", "--"]`, and `autoloadBunfig`, `autoloadDotenv`, `autoloadTsconfig`, and `autoloadPackageJson` all `false` (vibest runs in repositories it does not control, so it never autoloads CWD config files). Built `harnesses/` (`claude`, `pi`, `cursor`, `agy`) and `herdr-plugin/` are packed into one deterministic compressed archive and embedded once, unencoded, via `import archive from "..." with { type: "file" }`. On `vibestd` startup, embedded assets are materialized idempotently and atomically to `<VIBEST_HOME>/cache/assets/<version>-<hash>/` (with `0755` preserved on executable scripts and a stable `<VIBEST_HOME>/herdr-plugin` symlink); `VIBEST_HARNESSES` overrides embedded assets in tests.

`install.sh` (`curl … | sh`) detects OS, CPU (including Rosetta 2 on macOS), and `musl` on Linux, downloads `vibest-<target>.tar.gz` from the latest GitHub Release (one archive per target, `install.sh`, and `version`), unpacks `bin/vibest` to `~/.local/share/vibest/versions/<version>/`, and links `~/.local/bin/vibest` to it; it keeps the version before as well, for a `vibestd` and sessions still running it. The install never lives under `~/.vibest`, which holds data only.

npm / bun / pnpm (`npm i -g @vibest/cli@beta`, `bun add -g @vibest/cli@beta`, `pnpm add -g @vibest/cli@beta`): `@vibest/cli` declares **no `postinstall` script** and requires **no Node.js runtime**. `bin/vibest` is a POSIX `#!/bin/sh` launcher that resolves `$real_self_dir` (symlink-safe across `npm`, `bun`, and `pnpm`), detects the `<os>-<cpu>[-musl]` target, verifies `@vibest/cli-<target>` carries the exact same version as `@vibest/cli`, self-heals on first run by creating a temporary hardlink and atomically renaming it over `$real_self` (never mutating `pnpm` store inodes, cleaning up on failure), and falls back to `exec "$target_bin" "$@"` on read-only filesystems. On the 2nd and all subsequent runs, the binary runs directly with zero wrapper overhead. All 6 `(os, cpu, libc)` platform packages go 1:1 into `@vibest/cli`'s `optionalDependencies`.

`vibest update` detects the install method from `realPath(process.execPath)` (matching `/node_modules/@vibest/cli(?:-|$|/)` or `/.pnpm/@vibest+cli`, or `^(.+)/versions/[^/]+/bin/vibest$`) without relying on `VIBEST_HARNESSES`, and upgrades with the package manager that owns the binary's real path (`bun`, `pnpm`, or `npm` with its prefix) or `install.sh` for curl installs, passing the detected `<os>-<cpu>[-musl]` target. Before it installs, `vibest update` fetches the new version into a temporary directory, verifies `--version`, and runs `vibest daemon import-check` against `VIBEST_HOME`; when any check fails, nothing is installed and `vibestd` stays running. `update` and `doctor` report extra `vibest` binaries on `PATH` with the command that removes them. `vibestd` checks for a newer version at start and every hour (`VIBEST_NO_UPDATE_CHECK=1` disables it).
